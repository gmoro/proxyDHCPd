## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.

## 2024-05-24 - DoS via Truncated Option Payload in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic (`DecodePacket`), after checking for the existence of the option length byte, the code would directly attempt to extract the payload based on that length (`self.packet_data[opt_first+1:opt_len+opt_first+1]`) and increment the iterator, without verifying if the remaining buffer actually contained `opt_len` bytes. A crafted packet terminating midway through an option's payload would cause the packet data extraction and loop iteration to behave unpredictably or fail downstream, as it wouldn't crash directly on python slicing, but could leave invalid/empty option data that downstream code expects to be populated.
**Learning:** This existed because while an initial bounds check was added for the length byte itself (`iterator+1 >= end_iterator`), a secondary bounds check for the entire payload length (`opt_first+1+opt_len > end_iterator`) was missing. In binary protocol parsing, every dynamic length field must be verified against the total remaining buffer size before consuming bytes.
**Prevention:** Always implement a two-step bounds check for TLV (Type-Length-Value) parsing: first verify the length field itself is within bounds, then read the length, and finally verify the entire value payload fits within the remaining buffer before extraction.
