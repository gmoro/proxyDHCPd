## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.
## 2024-05-25 - Insecure Daemon Umask
**Vulnerability:** In `proxydhcpd/cli.py`, the daemonization process explicitly set the umask to `0` using `os.umask(0)`. This could cause any files or logs subsequently created by the daemonized process to be world-writable, allowing unauthorized local users to alter logs or potentially exploit file permissions.
**Learning:** Daemonization tutorials frequently use `os.umask(0)` as a baseline, but in a production security context, this explicitly opens file permissions to the maximum allowable by default. It existed due to boilerplate daemonization code being used without a secure file creation mask.
**Prevention:** Always use a secure umask such as `os.umask(0o022)` when detaching a process and dropping privileges/resetting environment states, to ensure newly created files remain secure and are not world-writable.
