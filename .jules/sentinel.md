## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.
## 2024-05-24 - DoS via Type-Mismatch Bypass in Fixed-Length Option Validation
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `SetOption` failed to enforce strict fixed-length limits because it compared a specs list to an integer length (`specs==length`), which silently evaluated to `False`. This caused fixed-length options (like `subnet_mask`) to fall back to the variable-length validation branch, potentially allowing malformed truncated payloads.
**Learning:** This existed because Python allows comparing lists and integers without throwing a `TypeError`, meaning silent type-mismatches in validation logic can degrade security constraints without failing loudly.
**Prevention:** Ensure variables used in strict boolean expressions are explicitly type-checked or correctly indexed (e.g., `specs[0]==length`) to avoid bypasses caused by mismatched types.
