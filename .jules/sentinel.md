## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.

## 2024-05-24 - DoS via TypeError in MAC Address Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DhcpPacket.str()` iterated through bytes of the `hwmac` field and formatted them using legacy division `/` to access an array of hex characters (e.g., `hexsym[data[iterator]/16]`). In Python 3, division results in a float, which causes a `TypeError` when used as a list index. This crashed the daemon when it attempted to log or print the string representation of a network packet containing a MAC address field.
**Learning:** This existed because the codebase was migrated or written with Python 2 compatibility in mind, where `/` between integers yielded an integer. The assumption that logging/stringification is safe led to an unhandled exception crashing the daemon processing unauthenticated network payloads.
**Prevention:** Avoid legacy division `/` for array indexing; use `//` or refactor string formatting to use built-in formatters like `"%02x"` or `.format()` which safely handle Python 3 types and avoid manual math indexing.
