## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.
## 2024-05-24 - DoS via Incorrect Field Length Validation Bypass
**Vulnerability:** In `pydhcplib`'s option setting logic (`SetOption`), the comparison `specs == length` was silently failing (comparing a list to an integer), dropping down to an improperly guarded `specs[1]<=length` check which incorrectly accepted variable length inputs for options that were supposed to be strict fixed-length (e.g., accepting 1 byte for an `ipv4` address instead of 4).
**Learning:** Python quietly evaluates comparisons between different types like lists and ints as `False` without raising errors, leading to unexpected fallback behavior in validation checks.
**Prevention:** Ensure correct indexing (e.g. `specs[0] == length`) when comparing lengths against configuration tuples/lists, and use explicit mutually exclusive branch constraints (e.g. `specs[0] == 0`) for fallback paths.
