## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.
## 2024-05-24 - Network Protocol Field Validation Bypass
**Vulnerability:** In `pydhcplib`'s `SetOption` method, a logic error in option length validation (`specs==length` where `specs` is a list and `length` is an integer) quietly evaluated to `False` due to a type mismatch instead of raising an error or returning `False` for the entire validation block. This caused execution to fall through to a less strict variable-length validation check, enabling malformed DHCP options (like a 5-byte server identifier instead of exactly 4) to be accepted.
**Learning:** This vulnerability existed because Python handles type mismatches in equality operations differently than compiled languages—it silently returns `False` rather than throwing an exception.
**Prevention:** When validating data against strict rules, always ensure data types match and avoid bundling mutually exclusive validation checks into single compound `if` statements.
