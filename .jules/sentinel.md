## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.

## 2024-05-24 - Insecure File Creation Mask in Daemonization
**Vulnerability:** The proxyDHCP daemonization process in `proxydhcpd/cli.py` used `os.umask(0)` when decoupling from the parent environment, which clears the file creation mask. Consequently, any files (such as logs or process IDs) subsequently created by the daemon would be world-writable (permissions 777 or 666 minus execute bit), allowing local attackers or other low-privileged users to tamper with or escalate privileges via these files.
**Learning:** This occurred because developers often indiscriminately apply standard 'double-fork daemonization' boilerplate (like the legacy Unix `os.umask(0)`) to decouple processes, without considering the security implications of file creation permissions in modern or shared-environment deployments.
**Prevention:** Always use a secure file creation mask such as `os.umask(0o022)` when daemonizing processes. This removes write permissions for group and others while allowing full permissions for the owner, preventing world-writable file creation vulnerabilities.
