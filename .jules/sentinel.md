## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.
## 2024-06-23 - Insecure File Permissions via Default Umask During Daemonization
**Vulnerability:** The daemonization process in `proxydhcpd/cli.py` used `os.umask(0)`, which sets the file creation mask to 000. This causes any subsequently created files (e.g., logs, PID files) to be world-writable (rw-rw-rw-), exposing the system to local privilege escalation or tampering.
**Learning:** This existed because `os.umask(0)` is commonly (but incorrectly) cited in legacy daemonization boilerplate to 'clear' the inherited mask, without realizing it leaves the process with no default permissions restrictions.
**Prevention:** Always use a secure umask, such as `os.umask(0o022)`, when daemonizing to ensure newly created files are only writable by the owner while remaining readable by the group/others (rw-r--r--), adhering to the principle of least privilege.
