## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.

## 2024-05-24 - DoS via Unhandled Exceptions in Network Packet Logging
**Vulnerability:** The daemon uses `packet.str()` to format raw network packet details for debugging or logging. This string representation logic contained legacy Python 2 syntax (causing `TypeError`) and assumptions about payload format (causing `KeyError` or `IndexError`). Because the log function is called asynchronously while handling incoming requests, a single unhandled exception triggered by a malformed payload would crash the entire ProxyDHCP server daemon.
**Learning:** This existed because logging and debug representations are often assumed to be "safe" operations and are not wrapped in bounds-checking or error-handling like the core business logic. However, since the data comes from a network trust boundary, any unhandled exception here acts as a Remote Denial of Service.
**Prevention:** When logging or formatting raw data received from an untrusted source, wrap the operation in a generic `try-except` block to ensure that a formatting failure does not cascade into a critical service crash.
