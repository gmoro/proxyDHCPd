## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.
## 2024-05-24 - DoS via Unhandled Exceptions in DhcpPacket.str() and GetHardwareAddress()
**Vulnerability:** The `DhcpPacket.str()` function and `GetHardwareAddress()` lacked proper validation when indexing extracted header fields and options. Specifically, the MAC address formatter expected a minimum length but didn't check, leading to `IndexError` on truncated packets. Furthermore, legacy code using floating-point division caused `TypeError` in Python 3.
**Learning:** These existed because the pydhcplib assumes ideal data arrays returned from packet unpacking and neglected bounds safety before array indexing.
**Prevention:** Wrap string formatting output methods in `try..except Exception` since failure to stringify a packet should not crash the primary daemon, and always strictly validate lengths (e.g., `len(data) >= 6`) before applying slice indexing or formatting.
