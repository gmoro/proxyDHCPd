## 2024-05-24 - DoS via Unhandled Out-Of-Bounds Exception in Packet Parsing
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `DecodePacket` did not check if the iterator was at the end of the packet data before attempting to read the length byte of a DHCP option (`iterator+1`). A specially crafted packet terminating exactly at an option byte code would throw an `IndexError: list index out of range`, potentially crashing the ProxyDHCP daemon handling the packet.
**Learning:** This existed because the original `pydhcplib` codebase assumed a well-formed network payload and blindly relied on `self.packet_data[iterator+1]`.
**Prevention:** Ensure all binary network data parsing functions bounds-check their read iterators against the maximum buffer length before consuming dynamically-sized tokens.
## 2025-02-25 - Type-Mismatch Bypass in Network Protocol Field Validation
**Vulnerability:** In `pydhcplib`'s packet parsing logic, `SetOption` had a type-mismatch error (`specs==length` comparing a list to an integer), causing the fixed-length validation to silently fail and fall through to less strict variable-length validation. This allowed malformed DHCP options (e.g., an `ipv4` option with length 3 instead of 4) to bypass validation and be set in the packet.
**Learning:** Python evaluates list-to-integer comparisons as `False` without raising an error. This can cause critical security and validation checks to silently bypass if the exact type is not verified or explicitly unpacked.
**Prevention:** Ensure strict typing and bounds checking when extracting length parameters from specification tuples/lists. Add explicit mutually exclusive conditions (e.g., `specs[0]==0` vs `specs[0]!=0`) to prevent logic fall-through.
